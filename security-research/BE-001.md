# BE-001 — Authorization / nonce / execution consistency

**Status:** Initial static pass; no confirmed vulnerability yet.  
**Target revision:** `689054ee14933cb2ee5bd54eadcd8dacbe1cc517`  
**Working branch:** `audit/everest-research`  
**Scope:** Base transaction (type 0x79) sender/payer authentication, nonce and replay checks, and consistency between pool admission and block execution.

## Initial control-flow map

### 1. Transaction identity and authorization

- `TxBaseSigned::new` computes the EIP-2718 transaction hash from the complete encoded signed envelope, including both auth blobs.
- `ResolvedSender::resolve` selects the explicit sender or recovers the EOA sender from the sender signature.
- `ResolvedSender::check_resolved_from` binds the resolved sender object to the signed envelope hash, preventing reuse with a different envelope.
- `TransactionAuthorizer::authorize` checks the binding and auth shape, verifies named sender/payer K1 signatures against the transaction-specific domain hashes, recovers open payer from `payer_auth`, and derives the delegation effect.
- Raw K1 parsing requires exactly 65 bytes and v in {27, 28}; the recovery path uses checked secp256k1 recovery.
- Sender and payer signature hashes use distinct domain prefixes. The payer hash substitutes the resolved sender. The signed body includes chain ID, fees, validity fields, account changes, calls, metadata, and payer.

### 2. Nonce model

- `nonce_key == 0`: protocol nonce, stored in sender account state.
- `0 < nonce_key < NONCE_KEY_MAX`: independent 2D channel stored in Nonce Manager mapping `nonces[sender][nonce_key]`.
- `nonce_key == NONCE_KEY_MAX`: nonce-free mode; sequence must be zero and replay is prevented by `TxBase::replay_id(sender)` plus an expiring replay ring.
- `NonceValidator` rejects stale sequences and `u64::MAX`; pool mode buffers future sequence gaps, inclusion mode requires exact equality.
- Delegation account changes are restricted to protocol nonce mode.

### 3. Pool admission path

`BaseTransactionValidator::validate_one_with_state_inner` performs structural checks and pool policy before `validate_base_tx_full`.

The full check:
1. Resolves and authenticates sender/payer.
2. Checks delegation code is empty or already an EIP-7702 indicator.
3. Reads sender protocol nonce and nonce-manager state.
4. Runs `NonceValidator::validate(..., NonceMode::Pool, now_ms)`.
5. Checks intrinsic gas, payer balance, and relevant fee limits.
6. Attaches invalidation watches for payer balance, delegation code, validity expiry, and the protocol/channel/replay storage slot.

### 4. Block execution path

`TxBaseExecutor::execute` enforces local chain ID and Everest activation at the execution boundary (not only in pool admission), derives the block's millisecond timestamp, and calls `authorize_and_apply`.

Within `authorize_and_apply`:
1. Enforces validity window.
2. Resolves sender.
3. Reads pre-transaction protocol nonce and runs `NonceValidator::validate(..., NonceMode::Inclusion, now_ms)`.
4. Authenticates sender and payer.
5. Installs delegation.
6. Advances the channel nonce, bumps protocol nonce later through `consume_sender_nonce`, or atomically records the nonce-free replay ID.
7. Checks intrinsic gas and fee caps/balance, then publishes TxContext.

On any pre-call validity failure the caller discards transaction journal state. A call-phase revert is different: the transaction remains included, consumes nonce and pays fees, consistent with the documented execution semantics.

## Initial observations

- The pool and inclusion paths share `ResolvedSender`, `TransactionAuthorizer`, and `NonceValidator`; their nonce modes intentionally differ only for future sequence gaps.
- Execution independently enforces chain ID and fork activation, covering direct block/Engine/P2P inclusion paths that bypass the pool.
- The nonce-free replay ID is signature- and fee-invariant but commits to chain ID, resolved sender, validity bounds, account changes, calls, metadata, and payer.
- Replay insertion validates the including block's millisecond timestamp, checks existing expiry, and checkpoints the correlated ring/mapping writes.
- The initial source review has not established an authorization bypass, replay bypass, or nonce-consumption mismatch.
